# Стандарт нового урока

**Действует с 6 ноября 2026; актуализирован 7 ноября 2026 по запросу владельца.** Обязателен для каждого нового урока и для каждой переделки существующего объяснения. Правила выведены из фактической истории изменений версий 0.6.0 → 0.6.1 → 0.7.0, а не из общих соображений: происхождение каждого блока — в [таблице трассировки](#откуда-взялось-каждое-правило).

Числа ниже — **пороги приёмки**, а не пожелания. Измеряемые требования проверяются подходящим тестом или измерением; зелёный тест не доказывает понятность ребёнку. Не все пороги уже автоматизированы: недостающие проверки добавляют при разработке урока. Где выбор свободен, это явно помечено как **свобода автора**.

Практический маршрут и шаблон ТЗ для нового урока и модернизации — в [руководстве подготовки](LESSON_WORKFLOW.md). Наличие стандарта не снимает ограничения PILOT-01 и не делает пилоты проверенными детьми.

Ссылки вида `CARD-01` ведут в [реестр правил](PRODUCT_RULES.md). Этот документ не отменяет реестр, а делает его исполнимым для урока. При расхождении документов действует [ASK-01](#ask-01--конфликт-останавливает-работу).

## ASK-01 — конфликт останавливает работу

**Любое противоречие или иная блокирующая причина — это вопрос владельцу, а не выбор исполнителя.**

Блокирующими считаются, в частности:

1. правило этого стандарта противоречит другому правилу, реестру или ранее данному указанию владельца;
2. для проверочных заданий нет сверенного источника (SOURCE-01/02/03);
3. требование нельзя выполнить, не нарушив контраст, читаемость, размер цели нажатия или NO-LEAK-01;
4. нужно сузить или расширить согласованную тему, диапазон чисел, число шагов или механик;
5. детскую пробу провести невозможно, а правило требует её результата;
6. техническая проверка не проходит по причине, которую нельзя устранить в рамках задачи.

**Порядок действий:** остановить спорную часть работы → сформулировать владельцу конфликт, 2–3 варианта решения и последствия каждого → получить ответ → записать решение в `docs/PRODUCT_RULES.md` с датой и пометкой «согласовано владельцем» → продолжить. Молча выбрать вариант, обойти правило или ослабить тест ради зелёного прогона запрещено. Отсутствие ответа — не согласие.

**Пример применения (6 ноября 2026):** урок «Римские цифры» упёрся сразу в SOURCE-03 (нет сверенных заданий учебника по теме) и в PILOT-01 (заморозка новых уроков до детской пробы). Работа была остановлена, владельцу заданы три вопроса, получены решения: 3 авторских задания утверждены как дополнение, урок делается видимым в каталоге без статуса «эталон», диапазон — I–XX. Все три записаны в реестре.

## 1. Каркас урока

Урок = **объяснение** (интерактивная модель) + **не менее двух игр разных механик** + **отдельная проверка**. Смешивать объяснение и проверку в одном экране запрещено (TEACH-01).

| Элемент            | Требование                                                                 |
| ------------------ | -------------------------------------------------------------------------- |
| Шагов объяснения   | ровно **3** для одного навыка; 4 — только по решению владельца (ASK-01)    |
| Игр-тренажёров     | **≥ 2**, механики различны по [реестру механик](#реестр-механик)           |
| Вход в игру        | отдельные действия для игр в панели инструментов на каждом шаге объяснения |
| Выход из игры      | «К объяснению», возвращает на тот же шаг                                   |
| Проверка           | запускается только кнопкой «Проверить себя» на последнем шаге              |
| Справка            | кнопка-иконка 44×44 с доступным именем, открывает отдельное состояние      |
| Возврат из задания | «Объяснение» → «К заданию» без потери ответа (HELP-01)                     |

**Запрещено:** игра начисляет баллы, пишет прогресс в хранилище или запускает проверочную сессию (GAME-01). Проверка внутри объяснения отсутствует: ребёнок может играть сколько угодно и уйти без оценки.

## Единая шапка теории и практики (HEADER-01)

- Название и тип — в первой строке, крестик закрытия справа; на узком экране тип переносится во вторую строку по CARD-04. Название не обрезается.
- Под заголовком — общий компонент точек `StepIndicator`, справа «Справка», а при наличии — отдельная кнопка справочника темы. Точка 9×9 px, текущая 13×13 px с кольцом 3 px, интервал 7 px, обводка 2 px; цвета и состояния определены в HEADER-01. Видимого счётчика нет. Количество точек равно числу шагов или заданий, повторные задания показываются отдельно, полный статус доступен скринридеру.
- Крестик практики сохраняет занятие и выходит; крестик теории закрывает окно. Иконки 21 px и кнопки 46×46 px, цвета, фокус и расположение едины; типографика заголовков общая согласно HEADER-01. Автотесты сравнивают стили, поведение и доступные имена на 320, 390, 768 и 820 px.

## 2. Подача: действие раньше объяснения

1. **На каждом шаге ребёнок действует.** Шаг без элемента, меняющего модель, не принимается: минимум одна кнопка/перенос/переключатель, изменяющая видимое состояние. Пассивный экран «прочитай и нажми Дальше» запрещён.
2. **Одно действие → одно видимое следствие.** Нажал знак — появились палочки; добавил I — изменилась запись и итог. Следствие появляется в том же экране, без прокрутки.
3. **Обратная связь причинная, а не оценочная.** Отказ объясняет нарушенное правило и показывает верную форму: «Четыре I подряд не пишут… IV — это 4». Слова «Неправильно», «Ошибка», «Молодец» в модели не используются.
4. **Пример доводится до итога** (MODEL-03): под записью всегда виден результат — `IV = 4`, `= 24 месяца`. Незавершённое равенство не принимается.
5. **Модель — чистая функция** (MODEL-01): расчёт и правила отказа живут в `src/engine/*.ts` и покрыты модульными тестами; компонент только рисует. Проверять истинность математики, а не только отсутствие исключений.
6. **Единая геометрия** (MODEL-02): повторное использование готовых примитивов обязательно. Календарь — `CalendarModel.tsx`, знаки — `RomanModel.tsx`. Новый урок не рисует собственную несовместимую версию уже существующей модели.
7. **Главное число никогда не перекрыто** (MODEL-04): указатель, стрелка или курсор не рисуется поверх значения, которое ребёнок читает. Положение пальца показывается контуром самого сектора. Стрелка через центр циферблата убрана по замечанию владельца 6 ноября 2026.
8. **Анимация только по смыслу**, уважает `prefers-reduced-motion`; при отключённой анимации урок полностью работоспособен.

## 3. Минимум текста: измеряемые бюджеты

Считается видимый текст; `sr-only` в бюджет не входит и не заменяет смысл для зрячего ребёнка.

| Место                           | Бюджет                                            |
| ------------------------------- | ------------------------------------------------- |
| Заголовок окна объяснения       | тема и тип по CARD-04; кегль ≥ 19 px, без обрезки |
| Название шага и инструкция шага | в `sr-only`, видимая строка отсутствует           |
| Строка состояния/следствия      | ≤ 60 символов и ≤ 9 слов                          |
| Подпись кнопки                  | ≤ 24 символа и ≤ 3 слова                          |
| Карточка знака/объекта          | символ + значение, без пояснительных фраз         |
| Служебная информация            | шаги — точки; тип карточки — текст по CARD-04     |

**Никогда не сокращать:** условие утверждённого задания, единицы измерения, причинную обратную связь, доступные имена элементов (CARD-01, READABILITY-01). Полные формулировки живут в задании и в справке, а не в шапке.

**Проверка:** тип, индикатор и кнопки доступны в компактной шапке на 320, 390, 768 и 820 px; текст не обрезан, горизонтальной прокрутки нет (CARD-04).

## 4. Карточки

- Радиус **16 px**, граница **2 px** цвета `--tone-edge`, мягкая заливка `--tone-soft`.
- Отступ внутри **12 px**, зазор между карточками **8 px**, сетка равных колонок.
- Состояния различимы **не только цветом**: активная карточка получает кольцо 3 px `--tone-edge` **и** меняет содержимое (появляются палочки/значение), плюс `aria-pressed`.
- Фокус клавиатуры: `outline: 3px solid #334d3a; outline-offset: 2px`.
- **Доступное имя содержит видимый текст** (WCAG 2.5.3): если на кнопке написано `V` и `5`, имя начинается с `V 5`, а пояснение идёт после него (`V 5 — знак V, это 5`). Прятать видимую подпись через `aria-hidden` и подменять её другим `aria-label` запрещено — axe ловит это как `label-content-name-mismatch`.
- Цель нажатия ≥ **44×44 CSS px**, на планшете запас до 48 px.
- Плотность премиальная, но пустая карточка без содержания не создаётся ради симметрии (DESIGN-01).

## 6. Управление: цвет и место

Инструменты модели — **виноградная панель** рядом с моделью. Навигация — **зелёная**, под панелью, отделена отступом и разделителем (CONTROLS-01). Проверяется геометрией: `nav.y > tools.y + tools.height`, и вычисленные цвета кнопок различаются.

Общее оформление пилотов и игр задаётся одним селектором `:is(.year-month-pilot-v2, .roman-pilot, .year-game, .roman-game)`. Новый урок добавляет себя в эту группу, а не копирует правила: иначе кнопки наследуют оранжевый цвет по умолчанию — так уже было найдено и исправлено 6 ноября 2026.

**Для каждой механики:** действие доступно пальцем, мышью и клавиатурой. Перенос обязателен там, где он часть выбранной механики; при переносе обязателен равноценный путь нажатием и клавиатурой (GAME-01). Не превращать выбор, указание или переключение в перенос только ради унификации. Ошибка не теряет объект; «Подсказка» и «Заново» доступны всегда.

**Перенос — настоящий (PLAY-02).** Реализуется pointer-событиями с захватом указателя и `touch-action: none`, а не HTML5 drag-and-drop: последний не работает пальцем. Для конструктора записи с табло объект ставится в любое место, уже поставленные объекты переставляются, а вытащенный за пределы табло объект возвращается обратно. Место вставки показывается меткой, объект следует за пальцем. Клавиатурный эквивалент: стрелки сдвигают выбранный объект, Delete убирает; фокус и выделение следуют за объектом. Для фиксированных мест, как в круге месяцев, перенос направляется к соответствующему месту; сохраняются видимая обратная связь, отмена и равноценный путь без переноса. Проверять автопрокрутку, если области разнесены по высоте.

## 7. Проверка знаний

1. Проверка отдельна от объяснения и открывается явным действием (TEACH-01).
2. Задания — только утверждённые: сверенные с учебником (SOURCE-01/02) либо авторские дополнения, согласованные владельцем поимённо (SOURCE-03). Условия и ответы учебника не меняются никогда.
3. **NO-LEAK-01:** до самостоятельной проверки нигде не показывается ответ текущего задания и полностью совпадающий решённый пример. Пределы модели подбираются так, чтобы ответ был недостижим; проверяется автотестом по всем путям показа, включая справку из задания.
4. Помощь (подсказка или открытие объяснения) переводит задание в `assisted` и начисляет опыт по правилу помощи (HELP-01).
5. Числовой ответ — экранная клавиатура видна на всех устройствах, включая компьютер; системная клавиатура на сенсоре не вызывается (INPUT-01).
6. Происхождение авторских материалов фиксируется в реестре, ТЗ и разделе «Родителям»; в детском интерфейсе меток происхождения нет (GAME-01 в редакции 6 ноября 2026).

## 8. Реестр механик

Новый урок и модернизация объяснения включают **не менее двух игр-тренажёров с разными механиками**. Выбирайте их по учебной цели, а не ради новизны: подходящую пару можно повторить из другого урока. Два визуальных оформления одного действия — не две механики; действия трёх шагов объяснения сами по себе не заменяют две игры. Ниже каталог примеров, не ограничение выбора:

| Механика                           | Где                    | Суть действия                                                                              |
| ---------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------ |
| Сборка кольца переносом            | «Собери год»           | расставить 12 месяцев по секторам пальцем/мышью                                            |
| Приращение модели                  | «Годы в месяцы», шаг 2 | добавить целый год/месяц и увидеть итог                                                    |
| Пошаговый маршрут по времени       | «Маршрут по часу»      | двигаться по пять минут от начала до события и обратно                                     |
| Словесное название по циферблату   | «Назови словами»       | выбрать название по положению стрелок, сопоставляя прошедшие или оставшиеся минуты с часом |
| Сопоставление групп и числа        | «Считаем месяцы»       | выбрать количество по кругам и отдельному сектору                                          |
| Сопоставление схемы и неизвестного | «Найди число»          | выбрать значение x по модели целого и частей                                               |
| Сборка цепочки решения             | «Собери решение»       | расположить исходное уравнение, обратное действие и ответ по порядку                       |
| Выделение равных частей            | «Собери половину»      | выбрать и убрать части целого, чтобы получить нужную долю                                  |
| Сборка цифр по разрядам            | «Собери число»         | собрать запись по заданным цифрам разрядов, включая ноль                                   |
| Изменение остатка под условие      | «Собери остаток»       | добавлять или убирать предметы, соблюдая ограничение делителя                              |
| Раскрытие соответствия             | «Римские цифры», шаг 1 | знак → количество палочек                                                                  |
| Сборка записи по знакам            | «Римские цифры», шаг 2 | нарастить запись, отказ по правилу                                                         |
| Перебор позиции знака              | «Римские цифры», шаг 3 | I слева/справа меняет значение                                                             |
| Указание на циферблате             | «Римские часы»         | провести пальцем по кругу к названному числу                                               |
| Конструктор под цель               | «Собери число»         | внести знак в любое место, переставить и вытащить обратно                                  |

**Свобода автора:** новая механика приветствуется, если помогает конкретному навыку, сохраняет причинную обратную связь, отсутствие оценки и доступность пальцем, мышью и клавиатурой. Перед сдачей опишите её и обоснование в ТЗ и добавьте в каталог. Не все механики требуют перетаскивания.
