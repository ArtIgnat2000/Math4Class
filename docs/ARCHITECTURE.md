# Архитектура и эксплуатация

## Стек и границы

React + TypeScript + Vite. Zod описывает и проверяет контент и сохранения.
Чистая предметная логика находится в `src/engine/` и не импортирует React, DOM или хранилище.
Интерфейс не знает арифметические правила конкретной темы: он выбирает рендерер по `task.type`.

```text
JSON → parsePack → ContentPack → планировщик → Session
                                 ↓              ↓
                              каталог      рендерер задания
                                                ↓ Answer
                                           checkAnswer
                                                ↓
                                     feedback / очередь исправлений
                                                ↓
                                          finishSession
                                                ↓
                                    Profile → storage adapter
```

### Модули

| Файл                   | Ответственность                                                          |
| ---------------------- | ------------------------------------------------------------------------ |
| `engine/content.ts`    | Контракт пакета, пять типов задания, схемы, перекрёстные проверки        |
| `engine/answers.ts`    | Безопасная нормализация числа, проверка и подпись ответа, перемешивание  |
| `engine/model.ts`      | Версионированные данные приложения, профиль, снимок занятия, результат   |
| `engine/lesson.ts`     | Создание очереди, попытка, повтор ошибки, переход, однократная фиксация  |
| `engine/progress.ts`   | Ступени, рекомендации, созревшие повторения, серии и награды             |
| `engine/references.ts` | Подписи и честное описание источников тем                                |
| `engine/dates.ts`      | Локальные календарные дни и русские числительные                         |
| `state/storage.ts`     | Чтение, проверка, предыдущая копия, экспорт, отказ записи                |
| `state/AppContext.tsx` | Связь состояния и UI, независимые профили, внешние события хранилища     |
| `App.tsx`              | Hash-маршруты, навигация, начало/продолжение, PWA, системные уведомления |
| `ui/`                  | Экраны, фокусное занятие, результаты, диалоги и доступные контролы       |

React Context выбран намеренно: нет отдельного внешнего store, нет нестабильных селекторов.
Запись выполняется в обработчике пользовательского действия, а не внутри React state-updater
с побочными эффектами. Синхронная ссылка хранит последнее состояние между быстрыми действиями.

## Конечный цикл занятия

`Session` содержит ID, класс, тему, режим, снимки заданий, первоначальное число заданий,
указатель, попытки, использование подсказки и проверенный результат текущего шага.

- `submitAnswer` не изменяет входной объект и не допускает повторную проверку того же шага.
- Каждая первая ошибка добавляет один повтор в конец. Повтор повторно не добавляется.
- `nextTask` не продвигается без проверки. После последнего ответа возвращает `null`.
- `finishSession` запрещает незавершённую очередь и не начисляет результат дважды для ID
  уже завершённого занятия в истории.
- Статистика точности — **только первая попытка**. Исправления учитываются отдельно.
- Подсказка сохраняет право продолжить, но не считается самостоятельным решением для ступени.
- Совокупные достижения записываются только при завершении. При выходе сохраняется черновик.

Порядок формируется один раз при старте. Снимок включает сами задания: изменение/импорт
пакета во время незавершённого урока не подменяет вопросы. Текущий непроверенный текст в поле
не сохраняется; проверенные ответы, подсказка и очередь сохраняются.

Все математические ответы задаёт автор. Для `division` контракт дополнительно проверяет
арифметическое равенство и границы остатка; ответ хранит две строки `quotient`/`remainder`.
Новые поля источников и разделов необязательны: старые пакеты и сохранения v1 совместимы.
Старые ID тем 4 класса не переименованы, пользовательские пакеты сохраняют приоритет.
Проверенные ответы и активные уроки не сбрасываются при расширении встроенного набора.

Нет `eval`, компиляции шаблонов, HTML из JSON или
загрузки произвольных удалённых изображений. Текст выводится через React с экранированием.

## Хранение v1

Ключи:

- `chislo:data:v1` — текущие данные.
- `chislo:backup:v1` — предыдущая валидная запись.

Перед новой записью предыдущий проверенный документ копируется в backup. Повреждённый
текущий документ не перезаписывает хорошую предыдущую копию. При старте сначала проверяем
основной документ, затем backup. При восстановлении из backup показываем предупреждение:
последнее действие могло потеряться.

`localStorage.setItem` атомарен для одного ключа, но два ключа — не транзакционная база.
При запрете, переполнении или недоступности API приложение не падает: остаётся текущая
сессия в памяти и заметное предупреждение с предложением экспорта. Успешная работа UI
**не равна успешному сохранению**, поэтому предупреждение нельзя игнорировать.

Экспорт включает профили, настройки, историю, незавершённые уроки и пользовательские пакеты.
Импорт целиком проверяется до замены, затем требует подтверждения. Перед восстановлением
и сбросом предлагается файл с текущими данными; предыдущая локальная копия также остаётся.

Ограничения размера: 1 МБ на входной контент-пакет; 5 МБ на файл копии; 2 МБ на суммарные данные
при добавлении пакета. Браузер всё равно может выделить меньше места, поэтому отказ записи
обрабатывается отдельно. Храним последние 180 результатов занятий и до 731 календарного дня
активности; общие счётчики остаются за всё время.

Другие вкладки принимают валидное событие `storage`. Это удобное обновление интерфейса,
**не многопользовательская транзакционная синхронизация**: одновременно заниматься в одном
профиле из двух вкладок не рекомендуется. Другая вкладка не видит непроверенный черновик ответа.

Дальнейшее развитие — IndexedDB + миграция v1 → v2 с проверкой, экспортом и возможностью отката,
а не параллельная вторая база с неявным источником истины.

## Даты

Дневная цель, серия и даты повторения — **локальные календарные дни**, не UTC.
Прибавление дней идёт через локальный полдень, чтобы не ошибаться на переходах летнего времени.
При возвращении во вкладку и раз в минуту день интерфейса обновляется.
Таймер не измеряет внимание ребёнка. Рейтинг по скорости отсутствует.

## Офлайн и публикация

Vite PWA / Workbox предварительно кэширует оболочку, встроенные материалы в бандле,
локальные шрифты, SVG и JSON-пример. Новая версия появляется как предложение; во время урока
перезагрузка не предлагается. Незавершённое занятие не требует сети.

PWA не включена в `vite dev`: это защищает разработку от старого service worker.
Офлайн нужно проверять на `npm run build` + `npm run preview` или опубликованном HTTPS-сайте.
Первая загрузка всё равно требует интернета. Очистка браузера удаляет и кэш, и прогресс.

Маршруты `#/learn`, `#/topics` и т. д. работают под путём GitHub Pages.
`base: './'`, относительные asset URL и локальный шрифт не привязаны к домену.
В браузерном коде нет запросов к sandbox-localhost или отдельному бэкенду.

## Проверки

```bash
npm run typecheck
npm run content:check
npm test
npm run build
npm run test:e2e
npm run format:check
npm audit --omit=dev
```

Unit-тесты проверяют все встроенные задания, форматы ответов, повторы ошибок, подсказки,
однократную награду, ступени, календарь, серии, изоляцию классов/профилей, повреждение данных
и отказ хранилища. `curriculum.test.ts` отдельно проверяет источники, разделы, старый формат,
математические ответы (независимый парсер арифметики, подстановки, массы, календарь, площади),
деление с нулевым частным/остатком и сохранение составного ответа. UI-тесты покрывают выбор класса, поиск, профиль без преждевременного submit,
отклонение неверного импорта и настройки, источники, фильтры учебника, два поля деления
и геометрию квадратной схемы.

Браузерные тесты используют **production-бандл**: холодный старт без профиля, смешанное занятие
с исправлением, восстановление после перезагрузки, импорт материалов, экспорт, разные профили,
телефон, адаптивность 320–1440 px, reload без сети, учебник/источники/страницы, полное
занятие с делением и ошибкой, продолжение составного ответа и новый банк офлайн. Axe проверяет основные страницы по WCAG AA
при выключенных анимациях. Автоматическая проверка не заменяет тест с ребёнком и скринридером.

CI проверяет PR и push. GitHub Pages публикует main только после проверок и браузерных тестов.
Секреты и отдельный сервер не нужны. Зависимости приложения прошли `npm audit --omit=dev`;
транзитивные advisory сборочного Workbox-инструментария отслеживаются отдельно.
