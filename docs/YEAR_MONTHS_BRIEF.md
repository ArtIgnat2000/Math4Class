# ТЗ пилота «Переводим годы в месяцы»

Статус: **согласовано направление 4 ноября 2026; реализация и наблюдение детей проверяются отдельно**. Основа: [концепция](LEARNING_VISION.md), [реестр правил](PRODUCT_RULES.md), [источник](SOURCE_AUDIT.md), [протокол пробы](PILOT_EVALUATION.md), [общий стандарт](DEVELOPMENT_STANDARD.md). При конфликте сначала согласовать с владельцем.

## Узкая учебная цель

Ребёнок знает календарное соотношение **1 год = 12 месяцев** и видит, что несколько лет — несколько групп по 12; дополнительные месяцы прибавляются отдельно. Круг сезонов показывает устройство года, **не объясняет, почему исторически в календаре именно 12 месяцев**. Не добавлять в этот пилот обратный перевод, дни или високосные годы.

## Сценарий

1. Круг: год и четыре сезона. Общий вид, а не проверочный вопрос.
2. Сезон: три подписанных месяца в выбранном сезоне; выбор не оценивается.
3. Двенадцать месяцев: видим единицу «один год» и её 12 частей.
4. Несколько лет: три отдельные группы по 12, запись `12 + 12 + 12 = 3 × 12`; один добавочный месяц отмечен **отдельно** как демонстрация `+ 1`. Это авторская **объясняющая модель**, не проверочный вопрос и не текст учебника. Не показывать числовой итог для подтверждённых условий «4 года» или «2 года 3 месяца» до проверки.
5. Только после объяснения действие «Проверить себя» открывает два сверенных условия с с. 47 (`four-years`, `two-three`). Новые проверочные вопросы — лишь после отдельного согласования, не в рамках этой задачи.

При необходимости ребёнок возвращается на шаг назад, открывает справку и выходит; просмотр не создаёт попытку или прогресс. Справка остаётся короткой и не подменяет математическую модель. Текстовый эквивалент модели доступен вспомогательным технологиям.

## Дизайн и техника

Визуал показывает именно отношение группировки, не только приятный календарь. Единая графическая система, подписи рядом с группами, различие не только цветом; понятные состояния управления. Основной текст ориентировочно не менее 16 CSS px, вопрос заметнее, числа и операции крупнее. Кнопка главного действия видна на типовом телефоне; длинный контент не обрезать ради запрета прокрутки. Проверить 320–390, 768–820 px, широкий экран, клавиатуру, фокус, reduced motion, контраст (обычный текст 4.5:1, крупный 3:1, значимая графика 3:1), часто используемые цели нажатия ориентировочно 44×44 CSS px. Офлайн/PWA, локальный прогресс, ID задач и математику движка не менять.

## Условия приёмки

- До проверки не отображается `27 месяцев` как решение условия «2 года 3 месяца» ни в окне пилота, ни в доступной теории темы.
- Модель показывает три различимые группы по 12 и добавочный месяц; ребёнок видит связь сложения и умножения.
- Не добавлены непроверенные задания; проверка начинается только отдельным выбором.
- Сценарии перехода/возврата/выхода, отсутствие горизонтальной прокрутки, доступные подписи и отсутствие утечки ответа покрыты e2e; `npm run format:check`, `npm run check`, `npm run test:e2e` проходят.
- Ручная проверка на поддерживаемом телефоне и Safari и качественная проба с 3–5 детьми по [протоколу](PILOT_EVALUATION.md) фиксируются отдельно; автоматические тесты не доказывают понятность. До этих данных урок не называть эталоном для остальных тем.

**Граница спринта:** новые уроки, глобальные награды, звук, аналитика, регистрация, внешние ресурсы и изменения хранения не входят. Общие правила выносить в реестр, детали этого навыка оставлять в данном ТЗ.
