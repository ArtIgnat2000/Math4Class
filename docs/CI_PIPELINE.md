# Проверки и публикация

Цель — сокращать ожидание без сокращения обязательного набора. Решение согласовано владельцем 7 ноября 2026. Выборочный набор не заменяет полный перед слиянием; правила источника, охвата, NO-LEAK и детской пробы не меняются.

## GitHub Actions

Один workflow `.github/workflows/check.yml` запускается на PR, на `push` в `main` и вручную. Отдельного запуска по `push` в ветку PR нет: иначе один коммит проверяется дважды. Новый коммит отменяет устаревший запуск того же PR или `main`.

1. `build`: `npm ci`, формат, полный `npm run check` (типизация, содержание, охват, все unit/UI-тесты, production-сборка), audit production-зависимостей. Команда `npm run test:e2e:shards:check` сверяет список полного набора Playwright со списками всех частей: каждый тест каждого проекта должен присутствовать ровно один раз; неполный, повторный или пустой набор останавливает CI. Результат сборки сохраняется как артефакт **этого запуска**.
2. `e2e`: четыре изолированные машины получают исходники того же запуска и одну и ту же сборку. Каждый запускает свою четверть полного набора, по одному работнику Playwright. `fail-fast: false` позволяет получить результаты остальных частей даже при ошибке одной. Отчёты об ошибках сохраняются отдельно для каждой части. Параллельное выполнение сокращает ожидание, но потребляет больше одновременно работающих машин и минут CI.
3. `check`: единый стабильный статус успеха требует успешного завершения сборки и **всех** браузерных частей. Пропущенная или неудачная часть не считается успехом. Если на GitHub настроена защита `main`, обязательным статусом должен быть `check`; настройки защиты и прав доступа необходимо проверять отдельно.
4. `deploy`: только для актуального `main`, только после успешного `check`. Публикуется тот же артефакт `dist/` из этого запуска, который проверяли браузерные части. Перед публикацией сверяется SHA текущего `main`; отдельный повторный прогон и отдельная пересборка в публикации отсутствуют. Ручной запуск из другой ветки не публикует сайт.

Для PR GitHub обычно проверяет синтетический merge-коммит. При слиянии `main` запускает новую проверку уже точного коммита `main` и публикует именно его артефакт. Успешный PR не означает, что после слияния публикация уже завершилась; проверяйте статус job `Deploy to GitHub Pages` и реальную версию сайта/PWA.

На 7 ноября 2026 прежний PR-прогон занимал около 10 минут 23 секунд, а прежняя публикация повторяла похожие проверки. Первый новый [прогон PR](https://github.com/ArtIgnat2000/Math4Class/actions/runs/42356929835) занял около 4 минут 12 секунд; все четыре части и итоговый `check` прошли. Это отдельные измерения, не гарантия будущего времени: дополнительно измеряйте время до окончания `deploy`, длительность частей и потребление CI. Сам шаг публикации до слияния в `main` не запускался. При изменении числа частей нужно менять матрицу и `E2E_SHARDS` вместе; тест конфигурации и проверка разбиения защищают от расхождения.

## В песочнице и локально

После `npm ci` и сборки можно быстро проверять конкретный сценарий без повторной сборки:

```bash
npm run check                              # включает сборку
npx vitest run tests/equation-pilot.test.tsx
CI=1 npm run test:e2e:built -- tests/e2e/equation-pilot.spec.ts
```

`test:e2e:built` **не собирает приложение**: после изменения кода или версии снова выполните `npm run build` или `npm run check`. `CI=1` запускает чистый preview, а не использует случайно оставшийся сервер. В этой песочнице два одновременных Chromium вызвали тайм-ауты; для полного прогона запускайте части последовательно. На машине с достаточными ресурсами для одновременного запуска задавайте разным частям разные порты и каталоги результатов:

```bash
CI=1 PLAYWRIGHT_PORT=4174 npm run test:e2e:built -- --shard=1/4 --output=.cache/e2e-1
CI=1 PLAYWRIGHT_PORT=4175 npm run test:e2e:built -- --shard=2/4 --output=.cache/e2e-2
```

Каждая команда выше запускает только указанную часть. В этой песочнице последовательные части прошли за 2,4 / 3,8 / 3,0 / 2,9 минуты; один тест в последней части прошёл после повтора. Полный локальный набор — `npm run test:e2e` или все четыре части; для слабой машины не запускать их все одновременно без измерения ресурсов. Локальная целевая проверка помогает в работе, но не отменяет правила [AGENTS.md](../AGENTS.md) о полном прогоне при изменении общего интерфейса и остальные проверки перед публикацией. Ускорение не доказывает удобство ребёнку и не заменяет ручную проверку источника или Safari.
