# Правила разработки «Числа»

Эти правила обязательны для изменений в этом репозитории. Если они расходятся с инструкциями среды выполнения, приоритет у инструкций среды.

## Релиз и контроль версии

- Единственный источник номера релиза приложения — `version` в `package.json`; синхронизировать `package-lock.json` командой `npm version <номер> --no-git-tag-version`. Не писать номер вручную в JSX, CSS или документации как актуальный.
- **Каждый набор изменений, публикуемый для пользователя через `main`, должен получать новый номер версии.** Для исправления — patch, для новой обратно совместимой функции — minor, для несовместимого изменения — major. Если в одной ветке несколько коммитов до одной публикации, достаточно одного повышения версии перед слиянием. Не повторно использовать уже опубликованный номер.
- На сайте номер текущего пакета должен постоянно присутствовать вверху бокового меню/гамбургера, быть читаемым на телефоне сразу после открытия (без прокрутки), и браться из `package.json`. В «Родителям» допускается дублирование того же номера.
- Перед слиянием проверять, что версия в меню соответствует `package.json`, что мобильное меню раскрывается и что номер виден при ширине 320–390 px. Положительный HTTP-ответ сервера **не доказывает**, что пользователь видит новую сборку: при расхождении сообщать номер видимой версии и проверять публикацию и PWA-кеш.

## Изменения интерфейса и учебного содержания

- Проверять затронутые экраны на маленьком телефоне и iPad в портретной ориентации, доступность управления с клавиатуры/скринридера и `prefers-reduced-motion` для анимаций. Для задания с цифровой клавиатурой при 768×1024 и 820×1180 изображение, поле, клавиатура и кнопка проверки должны помещаться без вертикальной прокрутки с запасом не менее 48 CSS px; кнопки клавиатуры — не ниже 44 CSS px. Не обрезать длинные задания ради этого требования: если содержание не помещается, оставлять безопасную прокрутку. Не размещать номиналы поверх фактурных изображений; числа и подписи должны читаться отдельно.
- На телефонах иллюстрированные карточки сортировки размещать по одной в строке: крупная предметная картинка занимает левую часть карточки по её высоте, значение/подпись — справа от картинки, вертикальные стрелки — справа от подписи. Не уменьшать изображение до миниатюры над текстом. На достаточно широких экранах допустим один горизонтальный ряд с горизонтальными стрелками; оставлять стрелки видимыми и сохранять перетаскивание. Проверять все виды таких карточек (массы, грузы, календарь), не обрезать содержимое ради отсутствия прокрутки.
- Иллюстрация задачи показывает только данные условия, не раскрывает искомый ответ. Различать дизайн разных единиц массы; не утверждать, что пустой ящик, контейнер или любой спортсмен весит ровно 100 кг.
- Сведения об учебнике и охвате курса держать в разделе «Родителям», а не на детских карточках. Наблюдения за детьми не подменять результатами автоматических тестов.

## Проверка и публикация

- Перед публикацией выполнять `npm ci`, `npm run format:check`, `npm run check` и затронутые e2e-тесты (при изменении общего интерфейса — весь `npm run test:e2e`). При изменении версии обязательно тестировать видимость номера в мобильном гамбургер-меню.
- В отчёте разделять реализованное, опубликованное в PR и уже слитое в `main`; не выдавать открытую ветку или запущенный предпросмотр за обновлённый сайт пользователя.

## Проверяемые правила продукта

- [Реестр правил и статусов](docs/PRODUCT_RULES.md) обязателен. Владелец может изменить, временно приостановить или отменить правило через чат/PR. Не делать исключений молча: при конфликте назвать правила, предложить безопасный вариант и спросить владельца.
- Номер страницы в теме не доказывает происхождение каждого задания. Скрывать неподтверждённые задания; для каждого доступного ребёнку задания требуется сверка конкретного условия с утверждённым первоисточником. Не использовать найденный в сети учебник до согласования точного издания владельцем.
- Объяснять визуально до проверки; предоставлять отдельное обучение и проверку. Изображение должно буквально соответствовать словам. Завершение урока — короткий вывод и главное действие; следующие непройденные темы заметнее уже пройденных; мобильный выбор класса подписан словами.
- Для фото учебника записывать издание, страницу и конкретное упражнение в `docs/SOURCE_AUDIT.md`; изменённые числа, новые сюжеты, примеры по таблице и темы только из оглавления не считать заданиями книги. В `src/content/approved.ts` привязывать видимое задание к этим данным и фиксировать его подпись, чтобы редактирование не открыло непроверенный вариант. Не удалять скрытый архив или прогресс; закрыть каталог, рекомендации, импорт и восстановление старой сессии. Исторические браузерные тесты скрытого банка хранить отдельно от CI, новые тесты проверяют настоящий доступный банк.
